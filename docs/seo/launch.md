# SEO-подготовка ПрофиСпорт

## Подготовлено в коде

- Уникальные title и description главной, магазина, мастерской, сервиса и информации покупателям. Заголовок карточки содержит название реального товара и город.
- `product.html?id=…` отдаёт название, цену, характеристики, описание и Product JSON-LD уже в исходном HTML. Интерактивная карточка затем работает как прежде. Сервер использует тот же публичный API каталога: остатки, очистка характеристик, фотографии и категорийные скидки не рассчитываются второй раз.
- `catalog.php` содержит обычные HTML-ссылки на реальные категории и товары, по 32 товара на страницу. Это дополнительный путь по каталогу; интерактивные фильтры главной сохранены. У страницы пагинации свой canonical.
- `sitemap.xml` формируется из текущей базы: основные страницы, категории и доступные товары с положительной ценой. Карта не хранит снимок остатков и обновляется вместе с импортом.
- `robots.txt` и метаданные зависят от явных настроек запуска. Никакой домен не выводится из HTTP Host. Для карточек canonical включает id, для категорий — категорию и страницу; рекламные параметры не входят в canonical.
- Личный кабинет, корзина и страницы ошибок помечены noindex. Параметры поиска и подбора на главной не создают самостоятельные индексируемые посадочные страницы.
- Разметка магазина содержит только адреса, уже указанные на сайте. Рейтинги, отзывы, график, сроки доставки и неизвестные фото не придуманы.
- При сбое базы сервер отвечает 503 и Retry-After. Недоступная карточка отвечает 404, а не 200 с пустой оболочкой. Так же обрабатываются некорректные id и пустые категории.

## До подключения домена

Изменения хранятся в отдельной ветке. Не объединять с main до готовности к установке: текущие workflows автоматически публикуют main на временный хостинг.
В `server/config.php` оставить `seo_public_url` пустым, `seo_indexing` — false. Карта сайта в этом режиме недоступна с кодом 503, robots запрещает обход, HTML серверных страниц содержит noindex. Для закрытого тестирования желательно дополнительно использовать пароль на весь стенд: robots не является защитой доступа.

Для установки нужен PHP 8.1+, PDO MySQL, mbstring и Apache mod_rewrite/mod_headers либо эквивалентные правила Nginx. Статический хостинг без PHP не поддерживает серверный SEO-слой. Существующие URL товаров остаются прежними.

## Запуск на постоянном HTTPS-домене

1. Перенести базу, изображения и код; проверить заказы, остатки, импорт из 1С и публичные цены. Новые файлы нужно включить в процесс публикации.
2. Проверить, что перенаправление с HTTP на HTTPS срабатывает до внутренних rewrite; выбрать основной адрес www/без www и настроить второй вариант на 301. Адрес пока неизвестен, поэтому эти перенаправления не добавлены.
3. Указать в закрытом конфиге `seo_public_url` как `https://ваш-домен` без пути и параметров. Сначала оставить `seo_indexing=false`.
4. На постоянном хостинге проверить исходный HTML главной и реальных карточек, канонические адреса, корректность Product/Offer, реальную цену со скидкой, 404 неизвестного товара и 503 при недоступной базе. Проверить фото и пагинацию каталога. Отдельно проверить реальные правила Apache — встроенный PHP-сервер не исполняет .htaccess.
5. Согласовать политику снятых с продажи товаров. Сейчас слой следует существующему API и исключает недоступные карточки. Для сохранения накопленного поиска у временно отсутствующих товаров потребуется отдельное состояние «нет в наличии» без удаления страницы, согласованное с учётом 1С; не подменять удалённые модели случайными товарами.
6. После проверки переключить `seo_indexing=true`, снять пароль стенда, убедиться, что нет серверных X-Robots-Tag/noindex от хостинга. Проверить robots.txt и sitemap.xml с HTTP 200 на выбранном домене. Отправлять в поиск только этот домен.
7. Подтвердить права в Яндекс Вебмастере и Google Search Console, отправить sitemap.xml. Выбрать HTML-файл/метатег либо DNS-подтверждение по возможностям кабинета.
8. Создать Яндекс Метрику; при необходимости GA4. Согласовать обработку данных и загрузку счётчиков с механизмом согласия сайта. Подготовить CSP для выбранных сервисов, проверить сбор событий после согласия. Счётчики пока не установлены, номера и аккаунты неизвестны.
9. Проверить карточки двух магазинов и мастерской в картографических сервисах: адрес, телефон, часы и ссылка на окончательный сайт. Подтверждение владельца может потребовать звонка или другого действия пользователя.

## События для аналитики

`catalog_view`, `product_view`, `add_to_cart`, `checkout_start`, `order_created`, `phone_click`, `directions_click`, `service_request_created`.
Заказ и заявку считать только после успешного ответа сервера, не по нажатию кнопки; исключить повторное событие при перезагрузке. Выручку брать из сохранённого заказа. Не отправлять в аналитику ФИО, телефон, email или текст обращения. Проверить существующие согласия, CSP и настройки перед включением внешних скриптов.

## Семантика и развитие

Начальный акцент: спортивный магазин Оренбург; велосипеды Оренбург; самокаты Оренбург; ролики и скейты Оренбург; лыжи и зимняя экипировка Оренбург; ремонт/обслуживание велосипедов Оренбург. Узкие страницы создавать по реальному ассортименту и полезным различиям, а не для каждой комбинации фильтров. Частотности и ожидаемые позиции пока не оценены: нужны данные поисковых сервисов и окончательная структура ассортимента.

Следующие материалы: выбор велосипеда по росту и типу поездок; различия городского и трюкового самоката; подготовка велосипеда к сезону; выбор лыжной экипировки. В размерах и совместимости использовать подтверждённые данные производителя, не выдумывать универсальные ростовки. Публикацию материалов и их перелинковку выполнять после проверки ассортимента.

После запуска ежемесячно смотреть индексацию, ошибки, запросы, поисковые переходы, обращения и заказы. По данным кабинетов выбирать следующие категории для улучшения. Директ — отдельная платная реклама и бюджет; для органического поиска он не обязателен. Google Workspace для этого не требуется.

## Проверки

`php tests/seo.php` — экранирование, безопасный origin, режим до запуска, canonical и JSON-LD.
`python3 tests/seo-http.py` — исходный HTML каталога/карточек, отсутствующие товары, ошибки параметров, robots и отключённый sitemap на одноразовой базе из существующего Store checks. Проверки выполняются для свежей и старой схемы БД.
Мобильная вёрстка, загрузчик и галерея товара также проверяются существующими регрессионными тестами.

На постоянном домене отдельно проверить страницы в инструментах Яндекса и Google, мобильную скорость и обработку изображений на фактическом сервере. Эти результаты невозможно подтвердить до переноса. Наличие корректной разметки не гарантирует расширенный сниппет или позиции.
