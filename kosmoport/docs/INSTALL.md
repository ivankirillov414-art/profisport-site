# Установка «Космопорт CRM»

Инструкция относится к отдельному приложению «Космопорт», а не к обновлению ProfiSport, ID Studio, «Космосферы» или FastGo. Рабочий адрес приложения планируется как `/kosmoport/`, вход сотрудников — `/kosmoport/crm/`. Перед публикацией проверьте, что этот каталог на выбранном домене свободен. Существующие сайты, базы и файлы не заменять.

## Что устанавливается

- **Архив исходников**: PHP, браузерные ресурсы, доверенные миграции схемы, шаблон конфигурации и инструкции. В нём не должно быть паролей, рабочих документов, базы клиентов, резервных копий или настоящего `config.php`.
- **Рабочие данные**: отдельная MySQL/MariaDB, закрытое файловое хранилище и частная конфигурация. Они создаются и переносятся отдельно от исходников.
- **Резервная копия данных**: отдельный конфиденциальный ZIP с манифестом, JSONL таблиц, файлами всех версий документов, SHA256 и версией схемы. Установка исходников сама по себе данные не восстанавливает; порядок переноса описан в [MIGRATION.md](MIGRATION.md).

Проект рассчитан на PHP 8.2+, PDO MySQL/MariaDB и работу через обычный браузер. Для ZIP операций нужна доступная PHP поддержка ZIP; её наличие проверяют на выбранном размещении. Серверные Node.js, shell, cron, Docker, внешние API и удалённый доступ к MySQL для штатной работы не требуются. Команды CLI из комплекта выполняются **локально** либо на другом сервере, где владелец явно разрешил PHP CLI. Не вводите их в файловом менеджере или FTP панели InfinityFree.

## Перед загрузкой

1. Выделите отдельную базу и отдельный каталог для «Космопорта». Запишите имя домена, фактический document root, пути PHP и хранилища из панели хостинга. Не подставляйте реквизиты существующей ProfiSport базы.
2. Проверьте HTTPS, версию PHP, `pdo_mysql`, доступ к своей базе и возможность записи в частное хранилище. Для резервного копирования дополнительно проверьте ZIP и лимиты из раздела ниже.
3. Получите исходный архив и опубликованный SHA256 через доверенный канал. Сверьте хеш локально до распаковки. Например, в PowerShell на своём компьютере: `Get-FileHash -LiteralPath '<исходный-архив.zip>' -Algorithm SHA256`. Угловые скобки здесь обозначают имя реально полученного файла.
4. Сохраните отдельную резервную копию существующих сайтов и настроек перед любым изменением каталога домена. Размещение нового приложения не даёт разрешения изменять другие проекты.

## Структура исходного комплекта: не перемещать `public/`

Исходный ZIP сохраняет соседние каталоги `app/`, `public/`, `config/`, `migrations/`, `tools/`, `docs/`, `deploy/`, `integrations/` и пустой защищённый `storage/`. **Не переносите содержимое `public/` в корень проекта:** PHP загрузчики и защитные правила рассчитаны на исходную структуру. Ниже условные абсолютные пути; `<account>` заменяется фактическим каталогом аккаунта.

```text
<account>/htdocs/kosmoport/
    .htaccess                  # маршрутизация в public/, если rewrite доступен
    app/
    public/
        index.php
        api/
        crm/
        assets/
        setup.php
    config/
    migrations/
    tools/
    docs/
    deploy/
    integrations/
    storage/                   # пустой защищённый каталог в исходном ZIP

<account>/private/kosmoport/
    config.php                 # предпочтительное место настоящего конфига
    storage/                   # предпочтительное место рабочих документов
```

При работающем корневом `.htaccess` адреса `/kosmoport/`, `/kosmoport/api/` и `/kosmoport/crm/` направляются в соответствующие точки `public/`. До публикации проверьте это на выбранном хосте. Если rewrite недоступен, сохраните структуру, задайте `base_path` равным `/kosmoport/public` и используйте реальные адреса `/kosmoport/public/`, `/kosmoport/public/api/`, `/kosmoport/public/crm/`. Красивый адрес `/kosmoport/` в таком варианте ещё не подтверждён.

Предпочтительно вынести **настоящую конфигурацию и рабочее хранилище** за document root. Полное разделение приложения на private/public допускается только с проверенным адаптером загрузки путей; текущую соседнюю структуру нельзя произвольно разнести по каталогам. Наличие схемы выше не означает, что полный private split уже проверен на InfinityFree.

Конфигурацию берут из `config/config.example.php`. Core загружает файл, указанный переменной `KCRM_CONFIG`, либо `config/config.php` относительно корня исходников. Если выбранный хост не позволяет задать `KCRM_CONFIG`, используйте поддержанный установочным комплектом закрытый путь/загрузчик; не рассчитывайте, что переменная среды появится автоматически. Фактический способ подключения private bootstrap на InfinityFree должен быть проверен при развёртывании.

## Защита частных каталогов на общем хостинге

Если настоящая конфигурация или хранилище остаются в дереве document root, допускается совместное размещение **только после проверки HTTP запретов**. При любом размещении защищаются также исходники приложения и служебные каталоги:

```text
<account>/htdocs/kosmoport/
    public/       # единственная публичная часть приложения
    app/          # запрет HTTP
    config/       # запрет HTTP
    storage/      # запрет HTTP
    tools/        # запрет HTTP
    migrations/   # запрет HTTP
    docs/         # запрет HTTP
    deploy/       # запрет HTTP
    integrations/ # запрет HTTP; локальные адаптеры не являются публичным API
```

Используйте защитные правила из комплекта, включая скрытые `.htaccess`; FTP клиент должен действительно передать эти файлы. Отключите листинг каталогов. PHP доступ к частным файлам должен сохраниться, прямой HTTP доступ — отсутствовать. Файлы документов выдаются только через авторизованный обработчик CRM, никогда через URL `storage/...`.

**Проверка на настоящем хосте обязательна до любых реальных документов и секретов.** В каждом закрытом каталоге разместите безвредный текстовый маркер со случайным именем; затем в браузере без сессии CRM откройте его точный HTTP адрес. Также проверьте попытку получить SQL миграцию, шаблон конфига и внутренний PHP инструмент. Ответы не должны раскрывать содержимое, листинг, исходный код или запускать инструмент. Ожидается отказ 403/404. Страница браузерной проверки хостинга, перенаправление на вход и существование `.htaccess` сами по себе запрет не доказывают: завершите браузерную проверку и повторите запрос. После проверки удалите маркеры.

Если хотя бы один закрытый файл доступен, не загружайте туда настоящую конфигурацию и документы. Исправьте размещение или выберите другой хост. Успешная локальная проверка не заменяет эту проверку InfinityFree.

## Настройка приложения и базы

Настоящий `config.php` хранится отдельно от исходного архива и Git. Значения заполняются по шаблону текущей версии:

| Параметр | Что указать |
| --- | --- |
| `base_path` | `/kosmoport` без домена; итоговые публичные ссылки должны работать под `/kosmoport/` |
| `storage_path` | Абсолютный путь к закрытому хранилищу, предпочтительно вне document root |
| `timezone` | `Asia/Yekaterinburg`; база хранит время в UTC |
| `environment` | `production` для настоящего размещения |
| `app_key` | Отдельный случайный секрет длиной не менее 32 символов; сохранить частным способом |
| `setup_key_hash` | SHA256 отдельного одноразового токена первичной настройки; пустое значение отключает создание владельца |
| `database.driver` | `mysql` |
| `database.host`, `port`, `name`, `username`, `password` | Реквизиты именно выделенной базы из панели хостинга; не предполагать `localhost` |
| `database.charset` | `utf8mb4` |
| `session` | Параметры по шаблону; HTTPS и защищённые cookie обязательны для рабочего размещения |

Тестовый SQLite драйвер предназначен для явно выбранных локальных фикстур. Не используйте его вместо рабочей MySQL базы на хостинге.

Схема устанавливается миграциями **из доверенного исходного комплекта**. Все таблицы приложения имеют префикс `kcrm_`. Не импортируйте SQL из неизвестного архива и не изменяйте `ps_cms_` или таблицы других приложений. Первичную настройку выполняют через предусмотренную страницу `setup.php` и одноразовый токен: токен нельзя передавать в URL. После создания владельца очистите `setup_key_hash`, закройте/удалите временную публичную страницу настройки согласно комплекту и убедитесь, что повторное создание владельца недоступно. Пароля владельца по умолчанию нет.

## Загрузка через FTP и проверка

1. Распакуйте исходный архив локально. Передавайте только файлы новой версии и защитные правила в выделенные каталоги. Используйте защищённый режим передачи, поддержанный панелью аккаунта; реквизиты FTP не помещаются в проект или исходный ZIP.
2. Укажите частные пути и базу в настоящем конфиге. Публичные страницы, API и CRM должны обращаться к одному настроенному приложению.
3. Проверьте HTTP запреты, затем установите схему и создайте владельца. Перед документами проверьте отказ неавторизованному пользователю. Исходный архив включает `CHECKSUMS.sha256` для членов архива, кроме самого этого файла; отдельный внешний `.zip.sha256` проверяет весь ZIP.
4. В обычном браузере откройте `/kosmoport/` и `/kosmoport/crm/`, войдите и проверьте работу под подпапкой: ссылки, вход/выход, CSRF для изменений, загрузку списка и сообщения ошибок. Запросы идут на тот же origin: `/kosmoport/api/index.php?r=...`.
5. Проверьте небольшой искусственный документ: загрузка, новая версия, история, авторизованное скачивание и отказ после выхода. Затем проверьте тестовый билет, повторный проход и конфликт импорта без настоящих посетителей.
6. Сделайте тестовую резервную копию, скачайте её локально и восстановите в отдельную пустую тестовую базу/хранилище по [MIGRATION.md](MIGRATION.md). Только успешное восстановление подтверждает пригодность копии к переносу.

Проверки не должны менять рабочие записи чужих приложений. Для приёма билетов используйте отдельно помеченные фикстуры и изолированную тестовую установку.

## Ручной обмен с приложением билетов

Пока используется явный JSON экспорт/импорт в авторизованном браузере. Файл выбирает сотрудник; передача идёт в тот же origin CRM и требует текущей сессии/CSRF. Проверяются версия формата, идентификаторы, повторы и конфликты; конфликт не разрешается слепой перезаписью. Не отправляйте файл через открытый URL, почтовый вебхук или внешний API клиент. Браузерная защитная страница InfinityFree не является успешным импортом.

Существующее офлайн приложение билетов сохраняется. Отметка сотрудника об оплате взрослого билета остаётся ручным подтверждением: она не проверяет платёж и не выполняет фискализацию. Автоматическая синхронизация, физический сканер, кассовый регистратор и печать требуют самостоятельной проверки; успешные PHP тесты этого не подтверждают.

## Лимиты и незаполненные параметры

Перед реальными данными запишите лимиты именно выбранного аккаунта: `upload_max_filesize`, `post_max_size`, `memory_limit`, `max_execution_time`, `max_input_time`, доступное место и ограничения FTP. Большой архив может не поместиться в один браузерный запрос. Не обещаются обход лимитов, фоновый cron, продолжение прерванного импорта или работа без браузерной авторизации. Исходники можно распаковать локально и передать FTP отдельными файлами. Варианты для больших резервных копий описаны в инструкции переноса.

Локальная проверка и сборка исходного комплекта выполняются из корня проекта:

```text
php tools/package.php --check
php tools/package.php --output build/kosmoport-source.zip
```

Если локальный PHP под Windows не включил ZIP, а совместимая DLL имеется в его собственной поставке, вариант запуска: `php -d extension_dir="C:/path/to/php-runtime/ext" -d extension=php_zip.dll tools/package.php --output build/kosmoport-source.zip`. Укажите абсолютный путь к каталогу `ext` именно своей поставки PHP; чужую DLL другой версии PHP подставлять нельзя. Эти команды не предназначены для запуска на InfinityFree.

Пока должны быть подтверждены при фактической установке: домен и свободный `/kosmoport/`, rewrite либо адрес с `/public/`, document root/private пути, способ загрузки закрытого конфига и `KCRM_CONFIG`, имя/хост выделенной базы, PHP расширения и лимиты, HTTP запреты, включение защищённого обслуживания/переноса в браузере и адрес его временной страницы. Ни один пример пути или токена в этой инструкции не является настоящим реквизитом. Успешное размещение и проверка на InfinityFree фиксируются отдельно от локальной сборки.
