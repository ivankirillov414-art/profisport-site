# Размещение исходного пакета

ZIP сохраняет `app/`, `public/`, `config/`, `migrations/`, `bin/`, `tools/`, `docs/`, `deploy/`, `integrations/` и пустой `storage/` на одном уровне. **Не переносите содержимое `public/` поверх остальных каталогов:** PHP bootstrap использует относительные пути между этими каталогами. `bin/` содержит закрытые CLI-инструменты ядра и недоступен по HTTP.

Предпочтительный вариант — весь проект вне каталога документов веб-сервера, а document root сайта направлен на `public/`. Настройте закрытый каталог файлов и настоящий конфигурационный файл отдельно. Доступность такого расположения проверяется у конкретного хостинга.

На InfinityFree с фиксированным `htdocs/` допустим отдельный каталог `htdocs/kosmoport/` со всем деревом ZIP. Генерируемый корневой `.htaccess` направляет `/kosmoport/*` в `public/*`, сохраняя расположение исходников, а каждый закрытый каталог получает собственный `.htaccess` с запретом HTTP-доступа. При включённом `mod_rewrite` публичный базовый путь — `/kosmoport/`, CRM — `/kosmoport/crm/`. Если модуль недоступен, используйте явно настроенный базовый путь `/kosmoport/public/`; API остаётся `api/index.php?r=...`. После распаковки проверьте реальные пути и возможности сервера. Наличие `.htaccess` в архиве само по себе не доказывает защиту хостинга.

1. Убедитесь, что `/kosmoport/` свободен. Не заменяйте корень ProfiSport, `/cms/`, Kosmosfera или другую установленную систему.
2. Проверьте SHA-256 ZIP по соседнему `.zip.sha256`, распакуйте в новый отдельный каталог и проверьте все записи `CHECKSUMS.sha256`. Файл manifest не включает собственную контрольную сумму. `SOURCE-PACKAGE.json` описывает формат пакета.
3. Создайте настоящий `config/config.php` из `config/config.example.php` непосредственно на сервере или в отдельном защищённом канале. ZIP его не содержит. Используйте имена полей из шаблона текущей версии, местные реквизиты MySQL и отдельную базу/префикс `kcrm_`. Не публикуйте конфигурацию и не добавляйте секреты в исходники.
4. Настройте публичный базовый путь и закрытое хранилище согласно шаблону и инструкции ядра. Выполните миграции и настройку владельца способом, предоставленным ядром CRM. Архиватор сам не подключается к MySQL и не выполняет SQL.
5. Проверьте, что запросы к `/kosmoport/config/config.php`, `/kosmoport/config/config.example.php`, `/kosmoport/app/bootstrap.php`, `/kosmoport/storage/`, `/kosmoport/migrations/`, `/kosmoport/tools/` и `/kosmoport/SOURCE-PACKAGE.json` получают 403/404 и не возвращают файлы, листинг или сведения об ошибках. Для проверки хранилища используйте только временный безвредный маркер и удалите его после проверки. До подтверждения запретов не загружайте корпоративные документы и другие рабочие данные.
6. Проверьте публичную страницу, `/crm/`, API с реальной сессией/CSRF, загрузку и защищённое скачивание документов. Ограничения InfinityFree проверяйте в браузере: внешние клиенты могут получать страницу браузерной проверки вместо JSON. Не обходите эту защиту.
7. Для переноса действующих данных используйте отдельную резервную копию и `docs/INSTALL*` / `docs/MIGRAT*` текущего выпуска. Исходный ZIP не заменяет выгрузку MySQL, документов и конфигурации. Проверьте восстановление на изолированной базе до переключения рабочего адреса.

`storage/documents/`, `storage/backups/` и `storage/tmp/` в исходном ZIP пусты. Рабочие документы, логи, выгрузки, архивы, пароли и конфигурация из исходного каталога туда не копируются. Права доступа назначаются под пользователя PHP на новом хостинге; архив не задаёт небезопасные всемирно доступные права записи.

Для сборки локально нужен PHP CLI 8.2+ с `ZipArchive`:

```text
php tools/package.php --check
php tools/package.php --output build/kosmoport-source.zip
php deploy/verify-source-package.php build/kosmoport-source.zip
```

Если `zip` отсутствует в минимальной Windows-сборке PHP, подключите поставляемый вместе с этой же сборкой `ext/php_zip.dll`, например `php -d extension_dir="C:/path/to/php-runtime/ext" -d extension=php_zip.dll tools/package.php --output build/kosmoport-source.zip`. Можно передать абсолютный путь к DLL одним аргументом `-d extension=...`. Не загружайте случайные DLL другой версии. `--check` не требует `ZipArchive` и не создаёт ZIP. Повторная запись существующего ZIP и его `.sha256` требует явного `--force`.

`verify-source-package.php` с тем же расширением ZIP проверяет внешний SHA-256, все записи манифеста, запреты на рабочие данные/конфигурацию и расположение файлов, затем разбирает PHP без исполнения приложения. Простые статические `require` должны указывать на присутствующие файлы. Динамические загрузки конфигурации, модулей и временного maintenance-шаблона перечисляются отдельно: их смысл проверяется при интеграции. Этот локальный отчёт не является проверкой работы CRM, MySQL или HTTP-защиты хостинга.

Архиватор отказывает при отсутствующих обязательных файлах, символьных ссылках в собираемом дереве, недопустимых путях и превышении лимитов. Каталог назначения не может находиться внутри собираемых исходных каталогов или `storage/`; отдельное разрешённое исключение — `deploy/artifacts/`, который всегда исключается из исходного комплекта и позволяет передать готовый ZIP без рекурсивного включения предыдущих сборок. В исходный пакет допускаются только типы файлов исходников/публичных ассетов; JSON — схемы, публичный `manifest.json` и два проверенных исходных файла `app/website/field-schema.json` / `default-content.json`. Точное исключение `app/core/config.php` сохраняет программный загрузчик конфигурации; настоящий `config/config.php` и прочие приватные конфиги по-прежнему исключены. Непредусмотренные типы и каталоги с рабочими данными исключаются. Проверяйте отчёт и содержимое ZIP при добавлении нового типа исходного файла.
